臨時騎士是騎士為單一任務找來的幫手，任務做完就清掉。
他是真正的 agent，有自己的提示詞、頭像和對話，所以你可以打開他的房間跟他說話。
他不是團隊成員：在群組裡沒有席位，圓桌也沒有他的位子。

## 請騎士找幫手

你不用自己建。
對騎士說一件可以拆成幾份、各自獨立進行的工作：

```text
比較這三篇論文。每篇交給一位幫手，再把他們的發現整理起來。
```

騎士每一份呼叫一次 `helper_create`，然後結束這一輪。
每位臨時騎士立刻開始工作。
他的回答會以新的一輪回到騎士的對話，跟 `message_agent` 的回答一樣。
回答都到了，騎士整理完，就呼叫 `helper_end` 清掉做完的幫手。

| `helper_create` 的欄位 | 內容 |
| --- | --- |
| `display_name` | 他的訊息上顯示的名字，1 到 32 個字元。 |
| `prompt` | 他是誰。 |
| `task` | 任務，要自成一體：做什麼、讀什麼、用什麼回答。 |
| `name` | 選填，永久的名字。沒填的話是騎士的名字加上下一個空的號碼，例如 `researcher-1`。 |
| `class`、`color` | 選填，他的外觀。 |
| `model`、`thinking` | 選填，預設跟騎士自己的一樣。 |
| `skills` | 選填，從 `skill_list` 挑的技能；技能 addon 開著才有。 |

臨時騎士沒有 agent、群組、封存、頻道整理和排程的工具，也不能再找臨時騎士。
兩個工具都是 `member` 層級。

## 上限與清理

- 每位騎士同時最多 4 位臨時騎士，整個 host 最多 12 位。
  到了上限，騎士最早結束的那一位會被封存，騰出位子。
  只有每一位都還在忙時，這個呼叫才會被拒絕。
- 臨時騎士「結束」的條件是：沒有任何工作在跑、沒有排隊、沒有等你回答的卡片，也沒有它的騎士傳來而還沒回的訊息。
  不需要騎士宣告。
- 結束的臨時騎士 24 小時後會自動封存。
- 封存的臨時騎士保留歷史。
  可以從封存頁復原，或用清除後通知上的**復原**。

用 `helpers` 設定改數字，或把工具關掉：

```ts
defineRoundtable({
	helpers: { perParent: 4, perHost: 12, archiveFinishedAfterHours: 24 },
	// helpers: false,  // 不提供 helper_create 和 helper_end
});
```

`perParent` 是 1 到 8，`perHost` 是 1 到 50，`archiveFinishedAfterHours` 是 1 到 720，或設 `false`，讓它們留著直到你清除。
超出範圍的值會讓啟動停下來，`perParent` 大於 `perHost` 也一樣。

## 他們住在哪裡

在 Discord，臨時騎士是騎士頻道底下的一個討論串。
他的訊息用他自己的名字和頭像顯示。
封存他就會封存並鎖住討論串，復原他則會重新打開討論串。
在網頁 app，臨時騎士是一個房間，列在他的騎士底下。

在擁有者 app 的房間列表，臨時騎士掛在騎士底下，各有一張小頭像和一個狀態：進行中、等你回答，或已結束。
**清除已結束的臨時騎士**在房間列表的選單、資料夾的選單和騎士的選單裡。
它會立刻封存，通知上有**復原**。
臨時騎士自己的選單有**封存這位臨時騎士**。
騎士自己清掉幫手時，它的房間會出現一行列出他們的訊息，同樣有**復原**。
