## Ask for an agent, and it can make one

You talk to one agent, the coordinator, in your server's entry channel.
Say what you want.

<Image src={agentCreate} alt="In the guide channel, a user asks for an agent that keeps reading notes. Guide answers that it made Notes in a new notes channel, with a prompt, an avatar, and a skill for saving links, and that it already started its first job." />

The new agent gets its own channel, an avatar, and a prompt.
It starts on its first job right away.
You can do this without editing a config file or restarting the bot.

## What it can do

<CardGrid>
  <Card title="Make agents" icon="rocket">
    Ask for an agent to research, edit, or tutor.
    Each one lives in its own channel and keeps its own conversation.
  </Card>
  <Card title="Write its own skills" icon="puzzle">
    An agent can write a skill and link it to other agents.
    It also remembers things between conversations.
  </Card>
  <Card title="Work as a group" icon="comment">
    Put two to six agents in one group channel.
    For each message, it picks who answers.
  </Card>
  <Card title="Tidy up for you" icon="approve-check">
    Ask it to archive an agent or rearrange the channels.
    Archiving deletes nothing.
    The channels keep their history.
  </Card>
</CardGrid>

<Image src={teamHandoff} alt="In the research channel, Researcher answers a request with two bullet points and notes that the result was handed to the editor channel." />

Agents can pass work to each other.

<Image src={agentStatus} alt="A Discord message listing three agents, Guide, Researcher and Editor, with their channels, models and whether each is idle or working." />

A status message in the server keeps itself up to date, so you can see who is doing what.

## Run it

<Steps>

1. Create a project.

   ```sh
   npx pi-roundtable init my-bot
   ```

2. Install, start PostgreSQL, and fill in `.env`.

   ```sh
   cd my-bot
   bun install
   docker compose up -d
   cp .env.example .env
   ```

3. Check the setup, then start the bot.

   ```sh
   bunx roundtable doctor
   bunx roundtable start
   ```

</Steps>

The first agent has a channel in your server.
Say hello and ask it for a second agent.
`/roundtable schedule list` shows any schedules the agents have.

## Connect your own tools

Add any MCP server from Discord with a private form, such as Notion or a calendar, and your code can give its tools to the agents you choose.
The same package lets an agent outside Discord send your agent a message and read the answer, and use the Discord channels you chose to share.
See [MCP connectors and remote MCP](/plugins/mcp-package/).

## If you write code

You can use these features without writing code.
To add a tool every agent can call, a slash command, an HTTP route, or replace part of the bot, write a TypeScript plugin.
A plugin can be tested without Discord or PostgreSQL.
See [Write a plugin](/plugins/first-plugin/).

Two plugins are ready to copy into your project: [dice and codex-images](/plugins/official-plugins/).

## Good to know

- It's built for one owner and one Discord server.
  You can let other people talk to the agents, but the risks of that are yours.
- It runs on Bun only.
  The package ships its TypeScript source, so there is no build step.
