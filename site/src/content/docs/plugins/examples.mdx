The repository keeps small, working plugins in [`examples/`](https://github.com/wayne930242/pi-roundtable/tree/master/examples).
Each has a test next to it that runs it without Discord or PostgreSQL, except `migrations.ts`, whose test needs a database.
The [plugin guide](https://github.com/wayne930242/pi-roundtable/blob/master/docs/plugins.md) embeds each file, and the repository's test suite fails when a block in the guide differs from its file.

| File | What it shows |
|---|---|
| [`tools.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/tools.ts) | A tool agents can call, with a minimum tier and a refusal the model can correct |
| [`reply-files.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/reply-files.ts) | A tool that attaches raw image bytes to the agent's reply and tests them with `harness.files` |
| [`holds.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/holds.ts) | A tool's `hold`, and a hold rule that sees every tool call, so a call waits for the owner's approval |
| [`prompt.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/prompt.ts) | A prompt section added after the core's prompt in every agent turn |
| [`seeds.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/seeds.ts) | An agent created on the first start, never overwritten afterwards |
| [`events.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/events.ts) | Handlers for turn start, turn end, team change, and shutdown |
| [`services.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/services.ts) | A long-lived timer service with `start`, `stop`, and `busy` |
| [`shared-services.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/shared-services.ts) | A service one plugin provides and others read with `get`, `find` and `lazy`, and a plugin that replaces it |
| [`migrations.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/migrations.ts) | Tables of the plugin's own, created by an idempotent migration |
| [`providers.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/providers.ts) | A plugin that fills the `images` provider slot |
| [`echo-runtime.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/echo-runtime.ts) | A replacement for the Pi runtime, filling the `runtime` slot |
| [`preflight.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/preflight.ts) | A check that refuses to start when a setting is empty |
| [`interactions.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/interactions.ts) | A slash subcommand added with `commands.add` |
| [`http.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/http.ts) | A route on the public listener |
| [`dashboard.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/dashboard.ts) | Extra lines on the dashboard message |
| [`selection.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/selection.ts) | Tools every agent carries besides its own |
| [`packages.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/packages.ts) | A Pi package whose extensions every session loads |
| [`session-tools.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/session-tools.ts) | The raw Pi extension form of a tool |
| [`channels.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/channels.ts) | A channel claim that owns conversations in some channels |
| [`study-room.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/study-room.ts) | A conversation kind of its own: a persona, a claim, and `context.turns` |
| [`support-desk.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/support-desk.ts) | A background target that sets what may be scheduled or delegated |
| [`fake-surface.ts`](https://github.com/wayne930242/pi-roundtable/blob/master/examples/fake-surface.ts) | A chat surface for an in-memory chat, and the plugin that contributes it |

## Full implementations

The examples above isolate one plugin contribution at a time.
For complete package implementations, follow the matching guides and source:

- Image tools that attach their output: [drawing guide](/plugins/drawing-package/) and [package source](https://github.com/wayne930242/pi-roundtable/tree/master/packages/drawing).
- An authenticated HTTP console: [web guide](/plugins/web-package/) and [package source](https://github.com/wayne930242/pi-roundtable/tree/master/packages/web).
- A held `repo_push` and an out-of-process Pi coding worker: [coding guide](/plugins/coding-package/) and [package source](https://github.com/wayne930242/pi-roundtable/tree/master/packages/coding).
- Isolated guest channels with a host-side credential broker: [sandbox guide](/plugins/sandbox-package/) and [package source](https://github.com/wayne930242/pi-roundtable/tree/master/packages/sandbox).
- MCP connectors and remote MCP endpoints: [MCP guide](/plugins/mcp-package/) and [package source](https://github.com/wayne930242/pi-roundtable/tree/master/packages/mcp).
- The official [`codex-images` copy-in plugin](/plugins/official-plugins/#codex-images) fills the `images` provider slot; its [template source](https://github.com/wayne930242/pi-roundtable/blob/master/templates/official/codex-images/plugin.ts) is a working provider implementation.
- The [official plugin guide](/plugins/official-plugins/) also links to the `dice` and `release-notice` copy-in sources.

To see what each part is for, start with [What plugins can add](/plugins/what-plugins-can-add/).
To run tests like the ones beside these files, see [Test a plugin](/plugins/testing/).
