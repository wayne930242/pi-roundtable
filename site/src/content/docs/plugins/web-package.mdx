`pi-roundtable-web` is the owner app of a host: a page on the host's HTTP listener where the owner talks to the agent team, answers its approval cards, stops a turn, sends files, switches yolo and long-running mode, and is notified on the phone when something waits.
It is also the console that came first, with conversation transcripts, memory notes and team status.

The plugin is a chat surface of its own, so a team of agents can live in the web alone: **a host with no Discord works fully**.
Each active agent and group has a room, and Home is the coordinator's.
A room is its own conversation, apart from the same agent's Discord channel.

## Install and requirements

```sh
bun add pi-roundtable-web pi-roundtable
```

Use Bun 1.4.4 or newer and pi-roundtable `>=0.25.0 <0.26.0`.
The app runs on the machine that owns the host data directory, and keeps its keys and files under `<dataDir>/web/`.
It needs an agent team (`agents` in the configuration), and authentication is mandatory: choose `none`, `password`, or a verifier such as Cloudflare Access.
Install the app and receive notifications over HTTPS.

```ts
import { cloudflareAccess, webConsole } from "pi-roundtable-web";

export default {
  // ...your roundtable settings, with `agents` and no `discord` if you like...
  plugins: [webConsole({
    verifier: cloudflareAccess({
      teamDomain: "example.cloudflareaccess.com",
      audience: process.env.CONSOLE_ACCESS_AUD ?? "",
      email: "owner@example.com",
    }),
    origin: "https://app.example.com",
  })],
};
```

Open `https://app.example.com/console/`; the page is the app.

## The owner app

| Where | What it does |
| --- | --- |
| Rooms | Home first, then agents, groups, and dispatch threads, with badges for working, a card waiting, yolo, and long-running. |
| A room | Messages with the author's character, Markdown, files, a live progress strip, a composer with upload and Stop. |
| Cards | Approvals with details, questions, questionnaires, and the card at a turn's time limit, answered in the room by any owner. |
| Agent profile | Name, prompt, model, thinking level, and the character creator. |
| Schedules | The team's schedules, with a confirmed cancel. |
| Table | A round table that seats every agent, and opens its room on a click. |
| Files | The agents' workspace: a tree, files highlighted by CodeMirror, and an editor whose saves check that a partner did not change the file meanwhile; new, rename and delete (to a restorable trash). |
| Settings | Color scheme and look, install, notifications for this device, and Log out. |

The Files pane shows the agents' working directory and scratch directory (and the `workspace.roots` you add) to the owner only. Every save is checked against the hash the file was read with, `.git` is read-only, symlinks that leave a place are never opened, and the editor's code loads only when a file is opened. The README has the full rules.

The table is a 3D scene where the browser has WebGL and an SVG table where it has not; add `?nogl` to the page address to see the SVG one.
Seat names are drawn at 11 px or more; where a canvas is too small for that, the seats are listed as buttons under it.

A turn waits `cardGraceSeconds` (120 by default) for a card; then it goes on without the answer, and the card stays open for a day.
An answer given later starts a new turn in the room.
Files of any kind up to `uploadMaxBytes` (100 MiB by default) are streamed to disk and given to the agent; a Cloudflare free plan caps a request body at 100 MB.

### Yolo and long-running mode

The room menu has two switches, kept per room and across restarts.
**Yolo** approves the held calls a rule allows, without a card, and writes a line in the room for each.
It never approves for a webhook or report turn, a call with named approvers, or a card that is the speaker's alone, and the destructive classes (`sudo`, `rm`, disk, power, services, docker, firewall, packages, force push, hard reset, `gh`, `crontab`) still ask.
A plain `git push` and a write outside the workspace are approved, and a push to `main` may deploy; list `shell.push` in `autonomy.yolo.card` of the host configuration to make it ask.
**Long-running** lets a turn go past its time limit, up to `autonomy.longRunning.maxSeconds` (four hours by default), then it asks on a card or aborts.
A banner shows while either is on.
The [core guide](https://github.com/wayne930242/pi-roundtable/blob/master/docs/plugins.md#hold-classes-and-yolo-mode) lists the classes and the guardrails.

### Looks

Agents are drawn as composed characters.
The page has a Modern look and a Camelot look (parchment by day, a night castle by night, gold rules, shield frames, wax seals), each in light and dark, picked per device in Settings.
`appearance.look` sets the host's default.

## Install on a device and notifications

The app is a PWA: a manifest scoped to the mount, a service worker that keeps the shell and never data, and icons (`icons.dir` replaces the shipped set).
Install it from the browser's Install option or Settings; on iPhone and iPad use Share, then Add to Home Screen, and open it from there.

Web Push wakes a device while no page of that owner is in view: when a card opens ("Card waiting", or "Long-running cap reached"), when an agent posts on its own, and for a notice the host sends.
Each owner turns it on per device in Settings, and can remove a device there.
Set `push.subject` (a `mailto:` address or an `https:` URL) unless `origin` is https; the VAPID keys are made at the first start in `<dataDir>/web/vapid.json`, and the file must outlive restarts.
Endpoints must be https on an allowed push service, and `push.endpointHosts` adds more.
With `push.preview` off a notification carries no message text.
From 23:00 to 08:00 on the console's time zone an agent's post and a notice are not pushed, while a card still is; `push.quietHours` (`{ start, end }` as `HH:MM`, or `false`) changes the window, and Settings shows it read-only.

## Configuration

| Option | Default | Purpose |
| --- | --- | --- |
| `auth` | required, or `verifier` | `{ mode: "none" }`, `{ mode: "password" }`, or `{ mode: "verifier", verifier }`. |
| `verifier` | none | Shorthand for the verifier mode: `cloudflareAccess(...)` or a custom function. Giving both throws. |
| `origin` | required | Browser-visible scheme and host. Writes must send this exact `Origin`. |
| `ownerId` | primary owner | Deprecated: the principal a verifier that reports no actor stands for. |
| `dataDir` | `./data` | Host data directory: `sessions/` and `web/`. |
| `mountPath` | `/console` | Route prefix. |
| `listener` | `public` | HTTP listener that serves the app. |
| `routing` | `hash` | `path` preserves mount-relative page links and history navigation. |
| `panes` | `rooms`, `table`, `workspace`, `overview`, `schedules`, `conversations`, `notes` | Ordered subset of those panes plus `skills` and `connectors`; `schedules`, `table` and `workspace` need `rooms`, and `workspace` needs a place to show. An explicit list is kept as written. |
| `workspace` | the agents' directories | What the Files pane shows. `workspace.roots` adds places, each with `workspace.roots.id`, `workspace.roots.label`, `workspace.roots.dir` and `workspace.roots.writable` (false unless set); `workspace.agents` and `workspace.scratch` set to `false` leave the agents' working or scratch directory out. A `dir` that is or contains `dataDir` stops the start. |
| `surface` | `app` | Key prefix of the app's rooms. Changing it starts every room over. |
| `cardGraceSeconds` | `120` | How long a turn waits on a card, above 0 and at most 3600. |
| `uploadMaxBytes` | 100 MiB | Largest file one person uploads, 1 byte to 4 GiB. |
| `push` | on with an https origin | Web Push; keys below. |
| `icons` | shipped icons | `{ dir }`: a directory of the five install icons. |
| `appearance` | `{ look: "modern" }` | `{ look }`: `modern` or `camelot`. |
| `title` | `Roundtable` | Page heading, title, and installed app name. |
| `presentation` | English | `{ locale, messages }` controls language, date formatting, and wording; English source strings are dictionary keys. A `zh-TW` locale uses the built-in Traditional Chinese (Taiwan) wording, and `messages` words single keys over it. |
| `features` | none | Object or public setup-context factory for party status, schedule counts, cleanup, skills, and connectors. |
| `relayNotes` | remote MCP relay note | Prefixes removed from relayed messages before display. |
| `exclude` | none | Predicate for conversation keys the console must not list or read. |
| `assetDir` | package `dist/` | Built page directory; set this only in tests. |

| Key | Default | Purpose |
| --- | --- | --- |
| `auth.mode` | required | `none`, `password`, or `verifier`. |
| `auth.trustNetwork` | `false` | `none` only: allow a TCP listener that reaches beyond this machine. |
| `auth.passwordEnv` | `ROUNDTABLE_WEB_PASSWORD` | `password` only: the variable that holds the password, at least 12 characters. |
| `auth.sessionDays` | `30` | `password` only: how long a login lasts, 1 to 365. |
| `auth.principal` | primary owner | `none` and `password`: the principal the session speaks for. |
| `auth.verifier` | required for the mode | `verifier` only: the request verifier. |
| `push.preview` | `true` | Whether a notification shows the first 120 characters. |
| `push.quietHours` | `{ start: "23:00", end: "08:00" }` | When an agent's post and a notice are not pushed, as `HH:MM` times on the console's time zone; cards always are. `false` turns it off. |
| `push.endpointHosts` | none | Extra push-service hosts; a leading `*.` allows subdomains. |
| `push.subject` | `origin` if https | The VAPID contact: a `mailto:` or `https:` URL. Push is off without one. |

## Authentication and the threat model

| Mode | Who is the owner | Use it when |
| --- | --- | --- |
| `verifier` | The person the verifier reports, linked to an owner. | A proxy such as Cloudflare Access signs people in. The only mode an agent on the host cannot forge. |
| `password` | The primary owner, after the password. | The app is reachable from the internet with no signing proxy. |
| `none` | The primary owner, whoever reaches the listener. | Only the owner reaches the listener: a unix socket, or loopback TCP. |

`password` serves a login page with no script, waits a second after each failure, locks every login for the rest of 15 minutes after ten failures (a global limit, because a client address behind a proxy is not trustworthy), and sets a signed `HttpOnly`, `SameSite=Strict` cookie that a new password invalidates.
`none` must be written out, warns at every start, and refuses a TCP listener that is not loopback unless `trustNetwork` is true.

**An agent whose shell runs as the host's user can reach whatever that user reaches.**
With `none` it can call the app as the owner over the socket, approve its own held actions, and turn yolo on; with `password` it can read the password and the session key.
Both resist the network, and neither resists a compromised agent.
Only a verifier does, because the agent cannot forge a signed token.
On a host whose agents run commands, keep Cloudflare Access (or another signing proxy).

The built-in `cloudflareAccess` verifier checks the signed Access token, team, audience, and allowed email.
A custom verifier that trusts a proxy header is only safe if clients cannot reach the listener directly and the proxy strips client-supplied copies of that header.
Every API, SSE, WebSocket, page, and static asset is authenticated before data is read, writes need the exact `Origin`, and the page sends no CORS headers.
Agent output is Markdown without raw HTML, and stored files are served as downloads under a sandbox policy.
Transcripts contain tool arguments and results, so secrets handled by tools may appear there; use `panes` or `exclude` to narrow what is exposed.

## Host integrations

Overview also lists stored owner workspaces and outside-agent conversations.
`features.party` supplies separately stored party channel status through `contains(key)` and `list()` returning `PartyView[]`.
`features.schedules.count(key)` adds workspace schedule counts.
`features.cleanup` supplies `startFresh(key)` and `deleteConversation(key)`; the latter returns `deleted` or `busy`.
The package validates key shape, ownership, exclusions and stored existence before invoking cleanup, shows confirmation dialogs, and returns 409 for a busy delete.
Without the cleanup hook, conversation data remains read-only.

`features.skills.catalog()` supplies source, description, groups, carriers and missing-file status.
`read(name)` returns the selected catalog entry's `{ frontmatter, body }`, never a request-selected path.
Set `errorDetail: true` to show the missing-file text or read error in the API response (cut at 300 characters) when the host's reasons are safe to show.
`features.connectors` supplies `gateways()`, `servers()`, `usedBy(server)` and an optional safe `adminUrl`.
Skills and Connectors fail startup when enabled without their hooks.

A feature factory receives public plugin setup context so the host can bind existing stores without renaming tables, grants or session paths.
Declare any extra service dependencies on the host wrapper's `requires`.
Application-specific wording belongs in `presentation`, not a cloned server or React page.

For the full threat model, the Cloudflare setup steps, the custom-verifier example, the WebSocket protocol, and option validation, see the [pi-roundtable-web README](https://github.com/wayne930242/pi-roundtable/blob/master/packages/web/README.md).
